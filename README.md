# raccoon-website

The product site at [raccoonbg.com](https://raccoonbg.com): the Raccoon
backgammon engine, playable and analysable in the browser. The research
write-ups live separately at
[research.raccoonbg.com](https://research.raccoonbg.com)
([lassehjorthmadsen/raccoon](https://github.com/lassehjorthmadsen/raccoon)).

## How it works

The network runs client-side. There is no server and no build step: Quarto
renders the pages, and `app/` is copied verbatim as ES modules.

```
app/engine/    board, move generation, encoder, evaluator, worker
app/ui/        SVG board, game loop, analysis panel
app/models/    the exported network (ONNX) + its .meta.json contract
app/vendor/    pinned ONNX Runtime Web build (self-hosted, no CDN)
test/          differential tests against fixtures from the raccoon repo
```

Move generation and the 26-channel encoder are ports of C++ (OpenSpiel) and
numpy (`raccoon/env/encoder.py`). Neither is trusted: `test/` compares them
against fixtures generated by the originals, including an end-to-end check that
this engine picks the same moves as the Python one on 1,000 recorded decisions.

## Working on it

```bash
npm install     # onnxruntime-node, for the end-to-end test only
npm test        # differential tests — these gate the deploy
quarto preview  # the site
```

## Refreshing the model and fixtures

Both are generated from the raccoon repo, which holds the weights and OpenSpiel:

```bash
cd ../raccoon
python scripts/export_web_model.py --checkpoint experiments/exp018-distill/checkpoints/ep22.pt
python scripts/export_web_fixtures.py
python scripts/eval_benchmark_pr.py --onnx ../raccoon-website/app/models/exp018-ep22-fp32.onnx
```

The last command re-scores the exported file on the BGSage benchmark. Quote
*that* number on the site: it describes the engine visitors actually play
(PR 0.9500, n = 14,693 — against 0.9498 for the PyTorch checkpoint).

## Moving the site onto raccoonbg.com

Until this is done the site lives at
`lassehjorthmadsen.github.io/raccoon-website`, and every path in it is relative
so both mount points work. Only one repository may claim a domain, so the
research repo has to let go of it first:

1. **raccoon repo** — point the docs at the subdomain: `site-url:
   https://research.raccoonbg.com` in `docs/_quarto.yml`, and `docs/CNAME`
   containing `research.raccoonbg.com`. Push, and wait for the docs workflow to
   write the new CNAME to `gh-pages`.
2. **Cloudflare** — add a CNAME record `research` → `lassehjorthmadsen.github.io`,
   DNS-only (grey cloud) until GitHub has issued the certificate.
3. Confirm `https://research.raccoonbg.com` serves the docs before touching the
   apex.
4. **This repo** — add a `CNAME` file containing `raccoonbg.com`, list it under
   `resources:` in `_quarto.yml`, push, then set the custom domain in
   Settings → Pages and enable Enforce HTTPS. The apex A/AAAA records and the
   `www` CNAME stay exactly as they are.
